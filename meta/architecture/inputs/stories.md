# User Stories (as-built)

> Reverse-derived from observed capabilities by `forge:reverse` on 2026-06-28.
> These stories were inferred from what the system does, not from original intent.
> Treat them as `doc-hint`/`reverse-engineered` until a product owner confirms them.

- **US-001** — As an **End User**, I want to authenticate and maintain a session so that I can use the CRM securely.
- **US-002** — As an **Administrator**, I want to model custom objects and fields (or apply a template) without writing migrations so that the data model fits my domain.
- **US-003** — As an **End User**, I want to create, read, update, and delete records through a generic, metadata-driven UI so that I can work with any object.
- **US-004** — As an **Administrator**, I want to control who can access which objects, fields, and records so that data is protected at three layers.
- **US-005** — As an **Administrator**, I want to tailor the UI per profile (portals, layouts, navigation) so that each role sees a fit-for-purpose interface.
- **US-006** — As an **Administrator**, I want to automate business logic declaratively (validations, dynamic defaults, procedures, automation rules) so that rules are enforced without code.
- **US-007** — As an **Administrator (Enterprise)**, I want to partition record access by territory so that large sales organizations can manage visibility by region/unit.
